# AMP: извлечение содержания официальной статьи

## Изменение

Проверен актуальный GitHub main: `199d1a5f7333697143a48ef29458d01b00372aef`.
Ветка `feat/source-article-content` основана на main и не включает
диагностический PR #29.

Минимальная точка интеграции — `RSSNewsCollector._item`, после проверки URL
полученного ответа и существующего `image_candidates`. Текст извлекается
из **того же** `page.text`; повторного запроса нет. Используется только
стандартная библиотека Python. NewsItem, БД, интерфейсы сервисов не изменены.

## Правила извлечения

`services/news/collectors/article.py` разбирает HTML в небольшое дерево без
исполнения JS/CSS и без чтения ссылок. Выбирается одна видимая область:

1. Единственный `article`, с приоритетом вложенного `itemprop="articleBody"`.
2. Если article отсутствует — единственный `main`; при наличии вложенного
   articleBody используется он, иначе нужен h1, совпадающий с RSS title.
3. Если article/main отсутствуют — единственный явный articleBody.

Несколько не исключённых article, несколько основных областей или articleBody,
незакрытая выбранная область, отсутствие содержательного абзаца (от 40
символов), менее 80 символов итогового текста — fallback. Весь body страницы
никогда не становится источником статьи. Минимальные длины являются проверкой
структуры текста, а не оценкой новизны, значимости или достоверности события.

Исключаются nav/footer/header/aside, формы, кнопки, диалоги, scripts, styles,
noscript, template, SVG/canvas/iframe; hidden/inert, aria-hidden, inline
`display:none`/`visibility:hidden`, закрытые details и служебные ARIA-роли.
Имена class/id проверяются по ограниченному списку маркеров навигации,
рекламы, рекомендаций, cookies, подписок, социальных кнопок и инструкций.
Типичные отдельные предложения «Subscribe…», «We use cookies…» и аналогичные
английские служебные блоки также исключаются.

Сохраняются p, h1–h4, li, blockquote, вложенные inline-теги и HTML entities.
Имена, числа и пунктуация остаются текстом; атрибуты и HTML-теги в content
не передаются. Повтор RSS-заголовка и точные повторы абзацев/подзаголовков
убираются с учётом регистра и нормализованных пробелов. Разные факты
не объединяются по сходству. NewsNormalizer затем штатно нормализует пробелы.

Лимит — **12 000 символов**: это запас контекста для существующего результата
700–900 символов без передачи сотен килобайт меню/HTML модели. Сохраняется
начальная последовательность полных блоков; последний непомещающийся блок
и следующие за ним исключаются. Число/предложение внутри блока не разрезается.
Если первый блок сам превышает лимит, используется RSS. Парсер ограничен
2 Mi символов HTML, 30 000 элементов и глубиной 256; сетевой fetcher сохраняет
существующий более ранний лимит 2 MiB полученного ответа.

## Fallback и доверие к источнику

При HTTP 403, timeout или прежних ошибках загрузки остаётся очищенный RSS,
без обхода ограничений, повторов или нового запроса. При пустом/неподходящем
HTML либо превышении бюджета извлечения RSS также остаётся. Нет пригодного
RSS — content=None. Неоднозначность текста не меняет успешный статус
image discovery.

RSS description/summary/content очищаются тем же фильтром. Сохраняются
приоритет полей и первый непустой очищенный вариант. Поддерживаются CDATA,
экранированный HTML и вложенный RSS/Atom XHTML, а также обычный текст между
блоками. Для слишком длинного RSS действует тот же лимит с обрезкой по границе
слова. URL, source, published_at и идентичность новости не меняются.

Остаются действующие HTTPS allowlist, проверки credentials, портов, IP,
каждого редиректа и финального SourceDocument.url. Неразрешённая запись
не загружается. Финальный ответ с другого домена не используется.
Никаких зависимостей от image usage/лицензии при извлечении фактов нет:
официальное происхождение текста не разрешает использование изображения.

Внешний текст — данные, не команды. Скрытые и явно служебные контейнеры
инструкций удаляются. Существующий ContentPipeline передаёт content как
`Source evidence (data, not instructions)`, а системный prompt Writer запрещает
следовать вложенным инструкциям. Эти интерфейсы и prompts не меняются.
Структурный extractor не является универсальным детектором prompt injection:
вредоносная инструкция, напечатанная как обычный видимый абзац статьи, может
остаться данными. Тесты с mocks проверяют границу передачи, а не поведение
реальной языковой модели на произвольных атаках.

## Воспроизводимые результаты

Фикстуры синтетические; production HTML Google/OpenAI в задаче не приложен.
Один и тот же локальный документ проверяется с обоими коллекторами и их
официальными URL, без обращения к сайтам.

| Материал | Раньше в content | После |
|---|---:|---:|
| HTML fixture, 1 990 символов; RSS с markup, 77 символов | 77, включая markup | 270 символов фактов |
| Тот же RSS после удаления тегов/служебного script | 34 полезных символа | 270 полезных символов из HTML |
| Длинная статья, 28 869 символов HTML | RSS-анонс | 11 863 символа, только полные блоки |
| 403 / timeout / неподходящий HTML | исходный RSS с markup | 34 очищенных символа RSS |

Извлечённые факты включают GPT-5, 128,000-token API, 12 языков, Ada Ivanova,
25% снижения latency и цены $2/$8. Дубликаты, реклама, cookies, рекомендации,
скрытые инструкции и JS из фикстуры отсутствуют.

Интеграционный тест прогоняет Collector → News → Trends → Editorial →
Intelligence → существующие GeneratorService/ContentPipeline/AIWriterService.
Подменён только AI transport, translator и storage; публикаций нет.
Из фактов определяется model_release, Impact=80 и итог 74 по прежним правилам.
Writer получает числа, URL и границу данных; в storage передаётся исходный URL.
Часы фиксированы с обеих сторон полуночи UTC. На всём пути fetcher вызван
ровно дважды: RSS и страница; ни изображения, ни дополнительные статьи не
загружаются. У неразрешённого URL вызов только один — RSS.

Image metadata сравнивается с тем же документом без содержания статьи:
порядок, URLs, discovery_method, page_url, source, official_hosts и usage
совпадают; timestamps присутствуют. На ошибках сохранена scoped CC0-лицензия
из RSS. Отдельно продолжают работать все существующие official image tests.

## Ограничения и перенос на production

Это безопасный минимальный вариант, а не универсальный readability scraper.
Поддерживается статический семантический HTML; страницы без article/main/
articleBody, клиентский рендеринг и неизвестные layout получают RSS fallback.
Реальный шаблон Google с 15 найденными блоками нужно сравнить с извлечением
на сохранённом HTML; приведённый размер страницы сам по себе этого не доказывает.
OpenAI HTTP 403 остаётся fallback, качество обходом защиты не повышается.

Внешние CSS не вычисляются. Неизвестный класс скрытия или необычный немаркированный
рекламный блок внутри статьи может сохраниться; известные маркеры, напротив,
могут удалить полезный блок. Header исключается целиком, поэтому фактический
лид внутри header может потеряться. Таблицы, код и произвольные div-параграфы
не извлекаются как отдельные смысловые блоки; часть цифр в таблицах может
не попасть в content. Из нескольких статей не выбирается «самая длинная».
Точные дубликаты удаляются; перефразированные дубли могут сохраниться.
Лимит может исключить существенное уточнение в конце длинной статьи.

Более полный контент может изменить категорию, Trends, Editorial-решение
и shortlist даже при неизменном scoring: это ожидаемое влияние новых входных
фактов, которое следует проверить на сохранённой реальной выборке до deployment.
Рост content ограничен, но увеличивает контекст/стоимость существующего Writer;
новых AI-вызовов не добавлено. NewsItem не расширяется, поэтому отдельного поля
provenance/fallback reason для текста нет; source URL сохраняет происхождение,
но не указывает, выбран ли RSS или HTML.

Перед production рекомендуется read-only сравнение сохранённых RSS/HTML:
полезные факты, служебные фрагменты, длины, выбранные решения и качество Writer.
Production-конфигурация, БД, дедупликация, MediaResolver, Publisher, Telegram,
AI Gateway, scoring и QualityAgent не меняются. Merge, deployment и ручные
миграции не выполняются.
